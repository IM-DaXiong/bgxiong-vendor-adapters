# 交给编程智能体的作者任务书

目标：基于本包公开 SDK 和现有样例，在独立目录为用户提供的 ComfyUI 工作流编写适配包。先读 README、DEPENDENCIES、SDK AUTHORING 与 schema；不要依赖主仓源码、内部报告或作者机器的数据路径。

1. 先确认用户图已在目标 ComfyUI 正常执行。取得 API 图/节点定义、素材角色、可调字段、最终输出节点及依赖文件名；不知道时明确询问，不猜节点或静默换图。
2. 已有工作流管理可直接表达的流程优先复用。需要自定义代码时，确认目标能力属于当前宿主支持范围；当前样例涵盖image.generate、video.generate及video.edit；按GENERATION-EXAMPLES索引选择最接近的完整子目录，并读该样例的宿主字段边界。根目录Wan指南只对应视频编辑。自定义可调标量字段放在 advanced 的闭集属性内，例如 advanced.motionPrompt；不能仅凭通用 SDK 支持根字段就假定应用能提交它。包检查、CLI成功与应用验收分别报告。
3. 初始化新作者工程。设置自己的 pluginId、包版本及操作身份；manifest 与 capability 一致。保留 vendor-sdk/template-lock 的完整性，依赖仅来自工程和公开SDK。
4. 在独立包实现图与平台语义。输入schema、UI声明、解析、图字段和结果保持一致；缺参数/未知字段/越界显式失败，正负提示词按原文处理，不自动修复或默认补齐。
5. 素材使用公开媒体租约/上传，凭据与网络通过 Host；不能直接读用户路径或绕开授权。明确最终输出，避免把预览作为成果。
6. 复用现有测试检查实际参数写入及必要反例。完成仓外 build/check/pack；生成原件摘要旁置清单，明确其不在runtime签名覆盖内。准备完整宿主配置而非两字段JSON。
7. 只向用户明确提供的服务做真实 submit/query。保存真实远端ID，受理后不自动重提；报告文件和回执位置。CLI结果与应用/安装版验收分别陈述。
8. 遇到已有行为回归、SDK合同缺口或约定时限/修正次数用完，保存当前成果并报告。不要改SDK、主程序或另建状态系统绕过。SDK全局发行状态不能因一个样例通过而晋升。

交付：完整独立源码、固定依赖与来源、标准runtime包、应用安装目录、配置及操作说明；分别标明离线、真实服务和产品入口实际验收状态。
