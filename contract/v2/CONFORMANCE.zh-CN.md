# 标准验证和 SDK 发布条件

设计定稿不等于SDK可用。任务级真实运行证据与全量候选验收分别记录；完整就绪状态见 [RELEASE-STATUS.json](RELEASE-STATUS.json)。任务局部通过不能提升尚未完成的全局案例。下游业务计划必须等相应基础Gate通过才恢复实施，不能靠改主程序使某个样例通过。

## Gate S0 规范自洽

schema可解析、引用可封闭、正反例符合预期；同一语义无重复字段；公开包不引用内部主程序类型。可验证的设计检查与运行测试分开。正文定义但未物化的标准profile必须在SDK实现批次完成，不能交给ComfyUI/工作台各自补齐。

## Gate S1 通用 SDK 和同源验证器

Rust/native/WASM/参考host/v2 worker/CLI使用同一版本及schema；SDK拥有独立workspace/lock/target，不改主程序构建、安装组件、生产配置或数据库。实际输入/结果做往返测试；required feature缺失明确拒绝。通用schema/form/registry不出现平台名称、URL、节点或厂商错误码。重复/冲突schema、非法media ID、越权配置仍明确拒绝；UI 无控件或控件呈现不匹配仅产生 ui_diagnostics，合法执行不依赖 UI。主程序的生产装配留在S4按模块验证。

## Gate S2 至少三类独立适配

用同一公开SDK和同一套测试工具验证：官方API形态（同步或流式文字/结构结果）、云端API形态（媒体上传、异步任务、错误/用量/恢复）、工作流形态（多媒体、声明式映射及复杂自定义代码）。可先用独立模拟服务做确定性离线测试；模拟测试不能写成已接通真实厂商。

至少两类场景必须使用同一业务能力，证明差异仅在adapter实现；再用相同配置声明两种能力，证明一模型多能力。具体真实服务由实施时已有授权的测试配置选择，标准不绑定某个厂商。

## Gate S3 外部作者无主仓接入

验收方只给作者公开发布包、目标API文档或工作流和明确测试任务；不提供src-tauri/ui/docs/dev。作者制作一个不在官方示例中的适配器，新增一个已有原语可表达的参数和一个namespaced操作；不得要求新增主程序枚举、注册代码或React组件。

证据包括独立目录构建、在公开参考宿主内安装、能力发现、参考配置UI、参数控件、执行、输出/用量/错误，以及SDK/runner公共源码和二进制在接入前后摘要不变。不得依赖尚未接入的主程序完成S3；生产UI的验证属于S4。参考表单导出的同一payload须经真实CLI/WASM执行，不以内部probe或静态表单替代。

### 原始证据组合与根上下文

作者路径以[作者证据引用合同](EVIDENCE-REFERENCES.zh-CN.md)为唯一引用规范。工件根只由调用方授权，JSON 不能增加权限。`independentAuthorEvidence` 及作者路径的其他 selector 必须显式提供三字段 file 引用；省略 root、两字段/字符串流记录、未知字段、失败后换根均拒绝。导入 selector 的授权根是内部 evidence 的唯一解释目录，不能改取 proof 父目录。

组合时保留原 proof、原 command record 和 stdout/stderr 的字节及 SHA-256。显式 `candidate`、`author` 等别名仍只使用调用方已授权的目录；外层保留名 `evidence` 不得覆盖被导入证据的局部 `evidence`。已经使用外层同根、显式工件别名的证据按相同规则解释，不需要增加第二条解析路径。

公开 `tools/compose_author_evidence.py` 生成只指向原件的 `AUTHOR_JOINED_REFERENCE_INDEX_V1`；外层 joined executions 和 Invocation selector 必须与该索引一致。命令中的 stdout/stderr/executable 保持原三字段引用及字节，不再依赖递归投影副本。索引准备不等于完整 C36 验收，仍需原始候选、浏览器、媒体、失败/恢复和清理证据。其余 13 条 joined 链及 candidate/repro 投影尚未迁移，具体清单见引用合同；这些旧消费者不能用于作者路径的失败回退或冒称已统一。

命令记录还须和实际文件闭环：CLI 身份与候选库存一致；argv 的输入、输出、工作区、包和 worker 与相应原文件、回执及诊断一致；输入/输出摘要、操作和请求 ID 相互绑定。`submit` 成功、失败的非零退出以及 `query --request-id` 回收原请求都必须有各自原命令和原回执，不能仅凭动词集合或某个独立成功文件验收。

## Gate S4 宿主闭环和升级

GUI/Creator/MCP同条件同能力/校验/结果；外部适配和项目自带适配使用同一准入检查和运行内核。工作台、画布、数据库属于host投影，不能泄露到adapter请求。同步、异步、事件、取消、服务重启/软件重启、凭据改变、包升级与媒体句柄重建都有证据。

S4按完整切换单元独立验收：用户数据离线备份/迁移/守恒/失败回滚通过；远端已受理任务只能回收原任务。该单元新版不存在官方专用旧参数旁路；GUI/F1/MCP等共用执行链的消费者同批切换。未接入单元继续原有完整代码，不是该单元失败后的回退路径。全仓历史路径尚未迁移时，必须列出范围与状态，不得把某个模块完成称为全软件已统一。

## 下游排期准入

S0定稿后编制独立SDK实现计划；S1–S3及独立发布包验收通过可标SDK_READY，不以主程序上线为前提。之后重新冻结ComfyUI最小闭环、视频工作台及其它模块的消费合同和任务边界，各自选择接入时间；相应S4随该单元接线完成后标MODULE_READY。业务计划只能提出标准缺口并回到公共标准修订，不能私增一套字段/生命周期。

覆盖检查用例：配置/密钥/权限；同名不同绑定；多模型/多能力；新参数/新操作动态注册；多模态输入；点框遮罩/时间/VFR；同步/异步/流式；部分输出/多输出；取消真实语义；断线未知受理；包pin与恢复；usage真实计量；未知字段/版本拒绝；开箱与独立作者。视频工作台与ComfyUI是其中两组需求样本，不能成为全部用例。
