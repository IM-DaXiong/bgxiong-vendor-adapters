# 统一开放适配标准

版本 2.0.0，设计定稿、独立 SDK 已实施；完整候选状态见 [RELEASE-STATUS.json](RELEASE-STATUS.json)。这里的“必须”约束下一版 SDK 与使用它的所有宿主和适配器，不表示现行安装版已有该能力。

## 1 一套标准与两个角色

适配器提供能力，GUI/外部智能体使用能力。适配器对接软件的 Vendor Adapter 标准；智能体操作软件的 Creator/MCP 标准。二者处于调用链不同端，不强行共用相同 JSON；它们共同消费同一份能力、参数、结果与错误语义，不能各自定义业务规则。

调用链固定为：GUI 或 Creator/MCP → 统一业务内核与能力目录 → 通用 adapter_host/worker → 所选适配包 → 目标服务。结果沿同链返回，宿主负责任务记录和素材入库。不能有“官方 API 直接进入私有 provider，第三方才走 SDK”的永久分叉。

一个模型或工作流可声明多条能力；一条能力可有多个操作。注册只从已安装、通过校验且被用户允许的包读取，不要求把每个操作加进主程序的编译时名单。

## 2 责任边界

主程序负责：包安装和信任、用户授权、配置与凭据保存、能力索引、通用 schema 校验和控件、媒体句柄、预算与取消、ai_tasks、持久恢复、用户界面、版本归属和结果保存。宿主不解释厂商端点、节点、错误码或私有状态。

适配包负责：声明模型/能力/输入/参数/输出；将公共输入转换成目标服务报文；上传、请求、查询、取消；把厂商结果、真实用量与错误转换为标准结果。适配包不能读写应用数据库、获取画布组件或直接写素材库。

平台辅助库可提供请求映射、工作流图处理等可复用代码，但仅被适配包依赖。宿主不因平台库存在而获得平台特判。ComfyUI 图的 source/output 节点、API 的 URL/header/body 都在这一层。

配置型适配和代码型适配是同一包接口的两种制作方式。通用模板能表达的用声明生成；复杂签名、工作流或协议用独立代码。不能为了某个服务给宿主增加一个私有配置解释器。

## 3 公共单一源

设计源是本目录；实现时由这里生成 SDK 类型、schema 验证器、模板和安装包副本。schema 一人一义，禁止在 app-contracts 再维护相同字段的手写镜像。应用专有的打开请求、草稿、画布 host、数据库 checkpoint 保留在 app-contracts，并引用公共定义。

公共包不依赖 src-tauri 主程序、ui、docs/dev、用户目录、仓库相对路径或内部服务。示例不是字段权威。作者拿到的发布包包含所有 schema/$ref、文档、模板、SDK、校验工具和测试资料；不得要求读取项目源码才能理解输入。

## 4 能力声明与可扩展操作

能力文档的固定结构见 capability-contract.schema.json。capabilityKey 表示业务语义，transportSlot 表示执行路由槽位；新增 generic 接受任何通过声明校验的业务能力，不要求新增宿主枚举；既有槽名仅作领域路由标识，不产生另一套协议。不能把 TTS 的 speech slot 当视频语音驱动。宿主界面按业务语义筛选，不按平台/模型名字猜。

标准保留的业务语义包括 text.generate、image.generate、video.generate、audio.synthesize、video.speech、video.edit；这是首批标准能力配置，不是未来能力的永久全局闭集。扩展能力与操作用 `<publisherNamespace>/<name>`，namespace 必须由包发布者身份证明；不能冒用他人或 std 保留命名空间。标准保留 std 命名空间；标准操作发布时须同时附唯一输入/输出schema并注册。未发布的 std 操作不得仅凭名称调用；S0 已发布 speech-v1 三个 std 操作（见 profiles/speech-v1）；其他具体操作仍使用作者自己的 namespace。业务语义与具体操作ID分离，不能同名改义。

能力定位由 package identity + modelId + capabilityKey + operationId/version 决定。宿主生成绑定账号/配置的运行时 capabilityId；作者不自行计算该 ID。显示名不是身份，同名不同配置必须区分。

operations 中每项具有独立 inputSchema/outputSchema/uiSchema、媒体槽、输出角色/数量、生命周期和可选特性。新增参数只改变包内对应 operation schema，不改宿主字段枚举。注册后先校验 schema 版本/引用/摘要和原语支持，再进入目录；相同操作版本不同摘要必须升级版本或拒绝，不能最后加载者覆盖。

支持、就绪和输入完整性是三层：声明支持不意味着凭据/运行环境就绪；已就绪但用户未给素材也不意味着不支持。目录不因缺素材删模型；提交总会重验当前配置、能力版本、输入、权限，不信任前端过滤。不可用明确提示，不选备用模型。

## 5 schema 严格与扩展开放并存

标准信封闭集；某个 operation 的 input 由它的已登记 schema 严格验证；**操作及参数的注册集合可扩展**。禁止宿主全局穷举所有厂商参数，也禁止把 pluginParameters 当无校验透传袋。

包内 schema 使用 JSON Schema 2020-12；只允许包内资源/公共随包资源的 $ref，不在运行时下载远程 schema。所有对象需定义 properties/required 和 additionalProperties:false；结构化字典仅在对应操作明确声明键/值 schema 时允许。拒绝非法递归资源和超预算 schema，不能以忽略未知约束作为成功。默认值只在用户初始化表单时按声明可见填入；正式提交已冻结，服务端不补缺失字段、不静默删字段。

通用 UI 原语：单行/多行文字、整数/小数、开关、枚举、可重复字段组、媒体槽、时间区间，以及图像/视频的点、框、遮罩。uiSchema 只描述控件、字段路径、分组、标签和帮助；约束来自 inputSchema，不能再写第二份上下限。它不能携带任意 JS/React、URL 脚本或宿主组件名。

必要控件无法呈现时标 unsupportedInteraction，不能隐藏该字段后仍提交，不能用 JSON 文本框冒充完整工作台。专用工作台可以提供更好的通用交互，但它产出的仍是同一 operation input。全新的交互需标准原语升级，不由单个平台插入主程序特判。

## 6 配置、凭据与服务地址

configurationSchema 允许适配包声明必需的非秘密配置项和帮助，凭据项只声明现行通用认证类型与槽位。宿主沿已有配置/凭据中心保存；密钥不进入能力文档、schema 默认值、示例、日志或运行时列表。

服务地址来自该绑定被授权的配置，静态官方地址可以在适配包中声明。宿主只验证网络授权和地址规则，不认识哪个域名属于哪个厂商；“官方API”“本地工作流”“云端”只作配置展示标签，不决定执行分支。

作者可用既有 broker 完成复杂签名，不能绕过权限读用户环境变量/本机任意文件或建立不受控网络。新增通用鉴权原语须独立版本化；标准不承诺当前 SDK 已支持所有鉴权方式。

## 7 输入媒体与应用隔离

适配边界使用公开 MediaInputV2/host-media：身份、种类、句柄、MIME、文件名和字节长度；尺寸/时长由受管媒体 probe 查询，不在输入信封私加元数据。源文件路径、storyId、trackId、canvas nodeId、数据库字段、writeMode:new_version、草稿和 React requestId 不传给适配器。

应用把对白音频、普通素材、导入文件、视频版本统一解析成受管不可变媒体，再建立本次句柄。包的 mediaSlots 声明 input 中媒体引用的字段路径、角色、种类与数量，主程序按描述通用校验，不为某厂商识别字段名。

几何公共基准为源像素，时间为毫秒半开区间；源尺寸、真实时间信息由媒体 probe 提供。平台坐标/帧索引/遮罩编码由适配器转换。精度不够或不可表达须拒绝/提出明确调整；不得直接裁切、变速或忽略选区。

大媒体走流式 broker，不塞进大 JSON 或默认 Base64。句柄只在合法会话/租约期内有效；持久 checkpoint 保存可重建的媒体身份，重启时发新句柄，不能保存旧 handle 当永远有效。

## 8 执行、流式事件、恢复与取消

复用 capabilities/probe/upload/submit/query/cancel 六类传输操作和 Invocation/Response 信封。业务 operationId 与传输 operation 分离，不能为每个业务加 WIT 方法。同步 submit 返回 completed；异步 submit 返回 accepted 和真实 vendorTaskId。宿主统一调度，不让包建第二任务表/后台轮询器。

流式输出是可选 stream-events-v1 特性：同一次 invoke 通过受管 host-stream 发有序事件，最终仍返回唯一 Response。它适用于文字片段、音频片段或进度，不能引入另一套终态。事件不能冒充 durable accepted；远端只提供同步流时不能伪造 taskId 来声称可重启恢复。无此特性仍可提供同步 completed，但不能宣称已实现流式。

异步 checkpoint 由宿主冻结 package/version/hash、model、operation/schema 摘要、真实任务号、所选配置引用及必要的包私有 resumeToken。resumeToken 只能按该版本公开的 resumeSchema 验证，不含明文密钥；包在 query 时解释它，host 不解析厂商内部格式。

重启恢复固定包版本/输入和输出目标，不能重新 submit。远端受理但响应丢失，若无可用幂等/查询证据就显式标不确定；不能保证不存在的 exactly-once。同步流中断但不支持远端续传时说明不可续，不暗中重新生成。

cancel 声明 remote、local_only 或 unsupported；local_only 只停止本地等待，不谎称服务端已取消。不允许借一个全局 interrupt 取消其他用户任务。关闭工作台不等于取消任务。

## 9 标准结果、错误和真实用量

沿现有 SubmitResult/QueryResult/Output/TerminalFailure 的语义升级，不定义厂商专属顶层状态。标准状态仅 queued/running/succeeded/failed/cancelled/expired；部分输出不自动等于终态成功。实际媒体尺寸、时长和格式来自产物探测；appliedParams 是实际应用证据，不能照抄请求。

结构化业务结果受 operation outputSchema 校验。多输出按声明角色和稳定顺序返回；不能通用层强制只取第一张图或一条视频。各具体操作可以声明自己的数量约束。

错误分清包无效、版本不支持、输入不合法、授权拒绝、上游调用失败、已受理任务失败；外层使用通用码，厂商原码只作诊断。用户文案由统一本地化投影；不能让官方API和第三方返回两种不可比较的错误合同。

成功响应中可解析的真实 tokens/characters/duration/credits/currency 用量按统一 usage 项记录，包含计量名、单位、十进制字符串数量、来源 reported；没有就不造，没有消耗则不假估。错误诊断、进度、成本都经同一标准回传，不在 host 为特定平台写解析器。

## 10 SDK 与应用版本的演进

下一标准为 major2，因为正式输入、动态 schema 注册、媒体与事件边界存在不兼容变化。重用现有内核并不等于保留旧字段/旧执行分支。版本协商发生在安装/发现阶段，不在提交失败后降级。旧用户通过离线配置/包/在途快照迁移升级；不能迁移的活动任务先完成或明确取消，不能丢弃或重提。

SDK独立构建和发布，不自动升级主程序。生产接入按完整切换单元分批进行：共享同一入口、绑定解释和执行/恢复链的调用者一起切换。未接入单元继续原有完整实现；已接入单元只接受新合同，禁止失败回退、双字段和双写。不同单元的过渡期版本归属明确记录，不按请求是否失败选择协议。共享v1只有最后消费者退役后才删除；不得提前破坏现有功能。

独立SDK的参考宿主不连接主程序数据库和安装目录；生产接入复用相同公共库，替换宿主端口装配。文档/SDK/validator/模板/示例及相应宿主必须锁同一协议和schema摘要发布，主程序模块按自己的版本锁接入。调用者缺少required feature必须明确拒绝。SDK_READY不代表任意主程序版本已经能够安装或运行v2适配包。

新增厂商/模型/工作流、已有原语覆盖的新参数/业务操作，仅更新适配包即可；新增基础传输、媒体、权限、交互原语才升级通用 SDK。每项 SDK 扩展必须用至少两类无关接入场景证明公共性，不准把平台私有字段上提。
