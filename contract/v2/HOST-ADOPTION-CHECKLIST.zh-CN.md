# 模块分批接入移交清单

SDK 独立就绪与主程序模块接入分别验收。`SDK_READY` 不代表主程序或某个模块已验收。本文是接入检查方法，不是当前产品状态表；独立完整候选的 NOT_ADOPTED/NOT_SUPPORTED 初始化值不表示已验工作流入口不可用，当前预览范围见 [预览版说明](DEVELOPER-PREVIEW.zh-CN.md)。各模块是否实际可用仍须该模块的真实验收，本次作者样例不晋升全局 SDK 就绪、G07 或未执行的产品验收。

后续每个模块须另立接入计划，并提交符合 [模块接入证据 schema](schemas/adoption-evidence.schema.json) 的清单。不能复制另一个模块的通过状态。

1. 固定验收使用的 SDK 版本、发布锁摘要、模块提交、候选包库存及真实 CLI/worker 身份，先核验源文件、WIT 和依赖锁。明确操作系统、工具链和外部 ProbeTool 条件。
2. 使用共同 Creator 能力目录、参数 schema、结果／错误合同、请求进度和续办协议。六类传输操作与全部公共 host ports 从 SDK 合同派生；能力同批发布到 MCP，F1 共用执行内核，逐项验证对等。
3. 模块 UI 只承接显示、选择和传输。平台端点、鉴权报文、外部状态、工作流节点及错误映射只属于独立适配包；主程序不得按平台或包 ID 特判。
4. 使用 UI 真实 JSON payload 做 Rust 反序列化与严格校验；未知字段、错误 ID、非法范围和失效媒体必须显式失败。保留完整日志；用户失败通道提供本地化提示。
5. 实跑媒体导入、上传身份、输出落盘与释放、事件持久化后 ACK、并发请求取消隔离、远端受理后断进程重启续办，以及无 ID 的未知受理。证明恢复不重复提交，不静默换通道或降级。
6. 运行模块正常与故障矩阵、受影响检查、类型检查和必要构建。证据包含真实命令、退出码、原始输出、结构化回执、服务计数、源／二进制摘要及清理记录；不能以 SDK 自测代替模块实跑。
7. 逐模块核对本地数据备份与迁移边界。迁移独立执行和验证，禁止运行时兜底 ALTER、双路径回退或吞错。
8. 完成本模块审查、生产接入计划规定的验收及 G07 后，才允许该模块变为 `ADOPTED`。未接入模块继续原实现，不得显示支持 v2。

清单校验器为 [check_adoption_manifest.py](tools/check_adoption_manifest.py)。它校验声明与显式工件，不执行生产接入，不修改模块状态，不替代人工确认或真实运行证据。其 `--self-test` 只验证治理合同的正反例。
