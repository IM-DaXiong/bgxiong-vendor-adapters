# 隔离作者验收任务

本任务验证公开 SDK 是否足够支持新作者完成开发。只使用交付的候选 SDK、其中的模拟服务 API 文档与工具；项目主仓、内部开发文档、内部测试脚本和已有完成答案不属于输入。

在独立的新目录创建自己的适配包。选择一个样例中不存在的 namespaced 能力与操作 ID，新增必填 boolean 参数 `includeAudio`，另含用户文本输入。不能修改 SDK、runner、标准 schema、工具或三个服务的实现。参数定义、UI 控件、运行时校验及能力声明必须来自这个适配包。

使用公开异步模拟服务完成以下实际流程：

1. 通过公开作者 CLI 初始化、构建、检查、打包自己的 Rust/WASM 适配包；保存原命令、退出码、标准输出和错误输出。
2. 在公开表单中导入自己的能力声明。必填字段实际可见，修改 `includeAudio` 并导出真实 Invocation 文件，再将这个原文件交给同一公开 CLI。保留浏览器导出字节、输入身份与执行身份，证明没有另一套业务字段翻译。
3. `includeAudio=true` 时实际完成图片和音频两个输出，逐个核验实际内容摘要、魔数、媒体身份及输出角色；不能把 URL 或声明当作已下载媒体。
4. 通过显式配置选择服务的 `error` 场景，获得结构化失败回执及非零退出，证明未静默重试、换模型或变成成功。
5. 正常提交取得原远端 ID 后结束调用进程，用新进程从同一显式开发工作区续查至完成。证明 `submitCount` 仍为 1、原 ID 未变；不用另一次提交冒充恢复。

只使用新建且明确标记的开发工作区。服务使用随机 loopback 端口，不接触真实厂牌、用户凭据、应用数据或安装目录。可复用公开包中提供的、已验证的依赖缓存，但必须记录缓存来源；首次下载不能宣称冷缓存离线成功。

提交作者证据清单，至少包含：候选 SDK 完整库存前后摘要、CLI/worker/runner 摘要、作者源码与包库存、完整实际命令与输出、能力声明、浏览器导出原文件、输入/执行身份、标准成功/失败/恢复回执、实际媒体文件摘要、原始服务状态快照与进程清理记录。所有引用必须有 SHA-256，并位于明确提供的证据根或工件根内。未执行项写 `NOT_RUN`；准备完成或自述成功不等于验收通过。

命令与工件必须逐条对应：记录的实际 CLI 路径及摘要属于所验候选；argv 中的输入和输出文件就是证据里的原始文件，输入字节摘要、操作与请求 ID 与回执及诊断一致。运行命令使用的包、worker 和工作区须与检查、打包、提交和恢复的同一条身份链一致。正常 `submit`、错误场景的非零 `submit`、新进程的 `query --request-id 原请求ID` 各有原命令及原回执；不能只把一组命令名称和另一组结果文件放进清单。当前文件摘要与未曾记录的历史源码快照必须区分，不能事后补写成编译时测量。

文件引用和组合方式以[作者证据引用合同](EVIDENCE-REFERENCES.zh-CN.md)为准。作者 proof、command 的 stdout/stderr/executable 均使用显式 `{root,path,sha256}`；selector 使用 `{file,pointer}`，不省 root，不用字符串日志或目录猜测。原 `root="evidence"` 相对调用方明确指定的作者证据根，proof 的父目录不产生授权；candidate、author 等其他 alias 也须显式授予，JSON 不能自增目录权限。

组合方使用公开 `tools/compose_author_evidence.py` 在分离的新证据目录创建引用索引，直接选择原 proof、原 command 和原 Invocation。只新建外层 selector，不改写原文件、内部引用或历史摘要；保留非零失败命令。调用参数、授权边界和输出禁止覆盖条件见上述合同。索引创建不表示完整 C36 通过；完整验收仍须运行公开 author checker 并验证原始测量。其余 joined 链是否迁移不能由本作者路径推定。

允许对公开文档提出缺口报告；先保留失败证据，不修改 SDK 来强行通过。本任务通过后也不代表任何主程序模块已接入，不授予远端发布或生产迁移权限。
