# 第三方适配器唯一开发与产物目录（硬约束）

用户要求：2026-11-02。适用于所有开发者及 Codex、Cursor、Claude、F1、MCP 客户端、子智能体；不依赖聊天记忆或个人配置。

1. 唯一存储根为 `L:/00Dev/bgxiong-third-party-adapters`。可脱离主程序自主安装的第三方适配器，其源码、厂商工作流、伴随程序、构建缓存、调试材料、安装包和发行候选全部放在此根内。禁止写回主程序 packages、临时目录、桌面或根外分支目录。
2. 当前主线源码在 `sources/main/packages/`；本次保全的分支版本在 `sources/<工作区标识>/packages/`；独立项目在 `projects/`；既有安装产物按原位置归档在 `artifacts/`。新产物使用 `artifacts/<pluginId>/<version>/`。新分支工作区也必须建在本根下，开始前记录源码 owner、分支和产物目录，禁止每开一次主程序分支就复制适配器。
3. 同一适配器只设一个当前开发 owner。历史分支副本保全供合并，不按时间或最大版本号覆盖主线；合并前核对未提交修改。主仓 Git 历史仍保留原记录，迁出不等于提交或推送完成。
4. SDK公共合同、通用模板、宿主/安装 owner 仍归主仓。厂商名称、平台映射和业务实现只归独立适配器。外置 SQL、数据库升级工具、数据库、用户媒体、任务回执不属于本次搬迁对象。
5. 已安装到应用数据根的运行副本及应用随包运行资源由安装 owner 管理，不直接移动或删除；开发和分发原件必须在唯一根下。通用 SDK 教学模板不作为具体适配器源码搬迁。
6. 构建入口必须显式读取唯一根；根或源码缺失立即报错，禁止回退旧目录、软链伪迁移或再次生成根外源码。主程序联调只消费适配器发布产物及公开SDK。
7. 改包内容须升版，禁止同版本覆盖不同内容；迁移不重新编译、不改签名、不改已发布包字节。清旧另核实际安装清单，禁止把搬迁当清旧授权。
8. 交付记录必须包含原路径、新路径、源码身份、实际包版本、验证范围和未验项。路径迁移验证不等于编译、安装或真实生成验收。
9. 所有智能体开工先读所在仓库 AGENTS.md；任务交接和子智能体提示必须携带此规则。新克隆/旧分支开始开发前先同步本规则，禁止用旧计划中的路径推翻本规则。执行前检查真实目标路径位于唯一根内。


**开发与交付边界（用户本轮追加明确）**：唯一根约束仅针对我方开发环境。交付用户后的安装目录、EXE旁分发目录、应用数据根、运行时资源布局、安装及升级协议全部沿用原合同，禁止要求用户拥有此开发路径。交付脚本默认保持 EXE 旁 `third-party-adapters/<pluginId>/<version>`；我方开发归档必须显式使用 `--development`，写入唯一根。随安装包输出的运行资源属于交付布局，允许按原合同生成。
